# 01 — Define Filename Search Within the Photo Workspace

Status: needs-triage
Category: enhancement
Priority: medium
Milestone: M4 — Faster photo-finding and tagging workflows
Blocked by: None

## Goal

Define a filename-search workflow that narrows the current Photo Workspace to photos matching a filename query.

## Proposed Direction

Consider a `file:` query form alongside existing tag and date queries, such as `file:DSC`. This must filter the current Photo Workspace rather than perform an index-wide search or introduce a second source of photos.

## Required Triage Before Implementation

- Decide whether `file:` belongs in the existing tag/date search field and command surface, or in a distinct workspace-filter control.
- Define matching semantics: filename versus full path, case sensitivity, substring versus prefix or exact matching, extension handling, and whitespace/escaping.
- Define how filename filtering composes with the current Photo Workspace view, database-search results, and the IPTC-empty filter.
- Define activation, replacement, clear/back behavior, selection repair, focus, scroll restoration, empty results, and keyboard workflow.
- Define whether multiple query forms can be combined and, if so, their syntax and meaning.
- Define stale-result and workspace-transition rules; filename filtering must never introduce paths outside its source Photo Workspace.
- Split approved behavior into implementation tickets with concrete acceptance criteria.
